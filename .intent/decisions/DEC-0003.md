## Context

The Intent package details could be inferred from two sources: (1) the npm registry metadata for `@dev-sixbyfive/intent-*`, which includes package descriptions, dependency lists, and keyword tags; or (2) the local monorepo at `H:/Intent`, which contains the actual README, CLI source, command definitions, and the package's own `.intent/` directory.

The first attempt at the page was built from npm metadata alone. This produced a page with incorrect CLI command names (`intent list-plans` instead of `intent plan list`), wrong status values (`paused` instead of `draft`), a missing package (`@dev-sixbyfive/intent` meta-package), incorrect flag names, and fabricated details not present in the real package.

## Decision

Always read the local monorepo at `H:/Intent` as the authoritative source. Specifically:

- `H:/Intent/README.md` for the full CLI reference, document format examples, integration configs, and design rationale
- `H:/Intent/packages/cli/src/cli.ts` and `packages/cli/src/commands/` for the exact command names and structure
- The package's own `.intent/` directory for any decisions made during the package's own development

npm metadata is only useful for the install command and version number.

## Consequences

- The documented CLI commands, flags, status values, and package names are accurate
- Any future updates to the package must be reflected in the site page manually — the page does not auto-update from the monorepo
- The meta-package (`@dev-sixbyfive/intent`) is documented as the recommended install, matching the README
